# Lucent Frontend Flow Spec

## Purpose
This document defines the page-by-page frontend behavior, expected user outcomes, and handoff rules for Lucent MVP.

## Page Map
1. `/` - Landing + Audit Input
2. `/audit/[id]` - Private Audit Result
3. `/r/[publicId]` - Public Share Result (PII stripped)
4. `/book` - Consultation Handoff
5. `/privacy` - Privacy Policy
6. `/terms` - Terms of Use

## 1) `/` Landing + Audit Input
### What this page does
- Explains value in one screen.
- Collects all audit inputs.
- Starts audit generation.

### Required sections
1. Header (brand + navigation)
2. Hero (clear promise)
3. Trust strip (supported tools)
4. Quick Start Presets (solo founder / 5-seat eng / 20-seat mixed)
5. Audit form (core interaction)
5. FAQ preview / credibility block
6. Footer links (`/privacy`, `/terms`)

### User expectations
- Understand Lucent in <10 seconds.
- Fill form quickly without confusion.
- No forced login before value.

### Success output
- Valid payload submitted.
- User routed to `/audit/[id]`.

## 2) `/audit/[id]` Private Audit Result
### What this page does
- Shows complete audit output for current user session.
- Offers AI summary.
- Captures lead after value is visible.

### Required sections
1. Savings hero (monthly + annual)
2. Priority Action Queue (top recommendations by impact and ease)
3. Per-tool breakdown (current -> recommendation -> savings -> reason)
4. Confidence labels (High/Medium/Low)
3. Confidence/assumption indicators where needed
4. AI summary card
5. Lead capture block (email + optional fields)
6. Share actions (copy public link)
7. Conditional CTA:
   - Savings > $500/mo -> strong consultation CTA
   - Savings < $100/mo -> optimization notify CTA

### User expectations
- Recommendations feel numeric and trustworthy.
- Can save/share report easily.
- Clear next action based on savings level.

### Success output
- Lead record created (if submitted).
- Shareable public URL generated.

## 3) `/r/[publicId]` Public Share Result
### What this page does
- Displays a safe-to-share audit view.
- Enables social distribution.

### Required sections
1. Public savings hero
2. Public per-tool recommendations
3. “Generated by Lucent” attribution
4. CTA to run own audit

### Data/privacy rules
- Never expose email/company/personal identifiers.
- Show only tool/spend/recommendation data safe for public visibility.

### Metadata requirements
- Open Graph title/description/image
- Twitter card metadata

### Success output
- Shared URL previews correctly on social apps.

## 4) `/book` Consultation Handoff
### What this page does
- Converts high-intent users into consultation bookings.

### Required sections
1. Short context summary (potential savings)
2. Booking widget or consultation request form
3. Expectation copy (response timeline)

### Success output
- Consultation event captured.

## 5) `/privacy`
### What this page does
- Explains data handling for form and lead capture.

### Required content
- What data is collected
- Why it is collected
- How public reports remove identifiers
- Contact channel for requests

## 6) `/terms`
### What this page does
- Defines basic usage terms and disclaimers.

### Required content
- Tool usage scope
- Accuracy disclaimers
- Liability boundaries

## Primary User Flow
1. Visitor lands on `/`.
2. Completes audit form.
3. Redirect to `/audit/[id]` with results.
4. Submits lead capture after seeing value.
5. Receives public share link `/r/[publicId]`.
6. High-savings users continue to `/book`.

## Edge/Failure Flows
1. Invalid input -> inline validation on `/`.
2. Audit computation error -> retry message + preserve form data.
3. AI summary failure -> fallback deterministic summary.
4. Lead submission failure -> retry without losing form state.
5. Missing/invalid public id -> 404 page with “run a new audit” CTA.

## Frontend Acceptance Checks
- Form state persists on reload.
- Route transitions are predictable and fast.
- Mobile layout remains readable and non-overlapping.
- Public page contains no PII.
- CTA logic changes correctly by savings thresholds.
- Quick Start Presets correctly prefill the form.
- Priority Action Queue is correctly sorted.
- Confidence labels render consistently with assumptions.
